# Security Policy

## Supported Versions

The current `macOS` branch is supported. Released versions are supported only
when explicitly documented.

| Version | Supported |
| ------- | --------- |
| Current `macOS` branch | Yes |
| Older releases | No, unless explicitly documented |

## Reporting a Vulnerability

Please do not report security vulnerabilities in public issues, pull requests,
or discussions.

Report vulnerabilities through GitHub private vulnerability reporting when it is
enabled. If private vulnerability reporting is not available, contact the
maintainers through a private channel before public disclosure.

When possible, include:

- Affected project, branch, version, or commit.
- A clear description of the vulnerability and expected impact.
- Steps to reproduce or a minimal proof of concept.
- Relevant logs, screenshots, or links.
- Any known mitigations or workarounds.

## Handling Process

Maintainers will review reports, ask follow-up questions when needed, and
coordinate fixes according to the severity and scope of the issue.

Maintainers may reject reports that are not security vulnerabilities, are not
actionable, or are outside the supported scope. Public disclosure should wait
until maintainers have had a reasonable opportunity to investigate and address
the issue.

## Safe Harbor

Good-faith security research that avoids privacy violations, data destruction,
service disruption, and unauthorized access beyond what is necessary to
demonstrate the issue will be handled as a responsible disclosure.
